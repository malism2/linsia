## 学习流程

保证用户在背词时心流不被打断，且能用最少的点击次数完成交互 ，学习流程由任务生成、背诵交互、结算反馈三个阶段构成。

1. 每日任务生成逻辑

   * 每天用户打开 App，需要动态为用户组装一个“今日词包”，词包由新词和复习词按比例混合而成。
   * 今日总任务 (N) = 每日固定新词数 (X) + 今日到期复习词数 (Y) + 昨日未完成遗留词数 (Z)
   * 出词顺序策略： 穿插模式，将复习词和新词混序打乱。先高频复习旧词找到自信，再学新词，最后用新词穿插旧词。
   
2. 核心背诵交互漏斗

   让用户在最短时间内划掉认识的词，集中精力死磕不认识的词。推荐采用标准的“卡片翻转”三步交互法：
    ```
       ┌──────────────────────────────────────────┐
       │ 步骤 1：看形听音 (正面)                   │
       │ [ Word: abandon ]  🔊                    │
       │ 选项/按钮:  [ 认识 ]   [ 不确定/不认识 ]    │
       └────────────────────┬─────────────────────┘
       │
       ┌─────────┴─────────┐
       [认识]               [不认识]
       │                   │
       ┌──────────▼───────────┐ ┌─────▼────────────────────┐
       │ 直接跳过，进入下一个   │ │ 步骤 2：看释义与例句 (背面)│
       │ (触发SM-2算法:满分)   │ │ 释义: vt. 放弃，抛弃      │
       └──────────────────────┘ │ 例句: Never abandon hope.│
       └─────────────┬────────────┘
       │ (点击下一步)
       ┌─────────────▼────────────┐
       │ 步骤 3：重新强制考核      │
       │ 输入拼写 / 选择正确释义     │
       └──────────────────────────┘
    ```
   关键交互细节： 
    * 正面（遮挡释义）：只展示单词、音标，并自动播放发音。给用户 1~2 秒的思考时间。
    * 认识（绿色按钮）：用户点击认识，卡片瞬间切到下一个词。在数据层面，该词直接出组（如果是复习词）或移入复习队列（如果是新词）。
    * 不认识/模糊（红色/黄色按钮）：翻转卡片展示详细释义、联想记忆法、权威例句。该单词在当天的词包中将被打上“未掌握”标记，稍后会在本次学习中循环出现，直到用户连续答对为止。
   
3. 复习算法的实时调度

   在单次背词过程中，如果用户点了“不认识”，这个词不能直接丢到明天，必须在接下来的几分钟内让用户再次看到。 你需要维护一个内存队列（Session Queue）：
    * 新词/错词初始生命值：设定为 2（意味着用户需要连续认出它 2 次才算通过）。
    * 队列循环：错词会被重新插入到当前剩余词包的后第 5~8 个位置。
    * 出组条件：只有当该词在当前背词会话中，生命值扣减至 0（连续答对），才算完成“今日学习”，并在后端真正修改 next_review_date（触发长期 SM-2 算法）。

4. 结算与激励机制

   背完最后一项单词后，绝对不能直接弹回主页，必须给予即时的正向反馈，这是提升留存率的关键。
      * 数据战报：展示今日学习成果（如：“今日斩获 30 词”、“用时 12 分钟”、“正确率 85%”）。
      * 可视化图表：展示今日新学、今日复习的比例饼图，以及连续打卡天数的日历。
      * 打卡分享：生成一张精美的社交媒体分享卡片（带有励志金句和 App 二维码）。
      * 明日预告：提示明天预计需要复习的单词数量，让用户心理有所预期。

## 交互

核心是：高频、盲操、沉浸感、无缝顺畅。

全面支持手势操作：不要只让用户点按钮。设计成类似 TInder 的卡片滑动——向右滑代表“认识”，向左滑代表“不认识”，上滑看释义。
* 向右滑动（或右侧大按钮）：代表“认识”。卡片飞出，下一词无缝滑入。
* 向左滑动（或左侧大按钮）：代表“不认识”。卡片翻转（Flip Effect），展示释义。
* 向上滑动（或点击卡片空白处）：代表“模糊/提示”。卡片半翻转，仅露出部分提示（如首字母或例句）。

三种卡片状态

1. 状态 A：全面遮挡（正面）
   * 视觉：大字号显示单词（如 persistent），音标。界面干净，没有任何中文。
   * 动作：卡片滑入的瞬间，必须自动触发音频播放 🔊。
   * 心理学原理：强迫大脑主动去检索记忆，而不是依赖眼睛看中文。

2. 状态 B：半遮挡（提示层）
   * 触发：用户点击“提示”按钮。
   * 视觉：展示英文例句，但例句中的目标单词被挖空（如：He is _____ in his usage.），或者展示词性（如 adj.）。
   * 动作：再次播放发音。状态

3. C：全面展示（背面）
   * 触发：用户划向“不认识”或点击“看释义”。
   * 视觉：卡片带有 3D 翻转动画转到背面。高亮显示核心中文释义（不同词性分行），下方展示助记口诀、词根词缀。
   * 底部变换：原本的“认识/不认识”按钮，变为一个大大的“记住了，下一个”按钮。

前端性能优化的“丝滑”法则
* 骨架屏与预加载（Preload Queue）： 前端内存中要始终维持一个长度为 5 的卡片队列。当用户在看第 1 个单词时，第 2、3 个单词的文本数据已经渲染完毕，第 2、3 个单词的音频文件已经异步下载到了本地缓存。
* 音频通道复用：不要每次放音都销毁并重新创建 AudioContext 或 HTML5 Audio 标签。应该全局复用一个音频播放器实例，切换 URL 直接播放，消除百毫秒级的播放延迟。
* 无感上报：用户点击“认识/不认识”时，前端应当立刻执行切换动画，并将用户的答题数据先压入本地缓存队列。每隔 10 秒或在背词结束时再异步打包上报给后端，绝对不能卡在原地等待后端网络接口返回。

错词的“立刻重现”视觉动效
* 交互细节：当这个错词在几分钟后再次出现时，卡片的左上角或背景可以带有微弱的橙色“再认”标记，提示用户“这是你刚刚没记住的词”。
* 通关动效：当用户终于连续认出它、生命值清零时，卡片可以向斜上方产生一个“消散/飞入已掌握”的粒子特效，给用户即时的成就感。

键盘与快捷键支持（针对 iPad/PC 端）必须支持纯键盘盲操：
* Space (空格)：播放/重新播放发音
* ArrowRight (右方向键) / J：认识
* ArrowLeft (左方向键) / F：不认识
* ArrowDown (下方向键)：查看释义/翻面

## 数据统计

核心统计指标与业务指标 (Core Metrics)你需要为用户和后台管理系统收集并计算以下核心指标：
* 连续打卡天数（Streak）：用户最在意的指标。只要今天完成了设定的每日任务，打卡天数 +1。
* 总掌握词汇量（Vocabulary Size）：在状态表中，状态被标记为“已掌握”或复习间隔时间（interval）大于一定天数（如 30 天）的单词总数。
* 今日学习时长（Study Duration）：前端累加用户处于背词界面且处于活跃状态的秒数。
* 正确率（Accuracy Rate）：首轮认出单词数 / 今日总过词数。这个指标能直观反映用户近期的记忆质量。

前端可视化图表设计
1. 打卡日历（Calendar Heatmap）
   * 视觉：类似 GitHub 的绿墙，或者标准的月历。
   * 交互：点击某一天，可以弹窗显示那一天“背了什么词”、“用了多少分钟”。
   * 防断打卡功能：商业 App 常见的“补签卡”机制，本质上就是后台修改某一天的汇总数据。
2. 词汇量掌握分布（漏斗图/堆叠条形图）将用户在这本书里的所有单词状态分为四个梯队：
   * 未开始：完全没见过的词。
   * 生词（学习中）：刚开始背，复习间隔小于 3 天。
   * 熟词（巩固中）：连续答对多次，复习间隔 3~15 天。
   * 已掌握：复习间隔大于 15 天，短期内不会遗忘的词。
3. 每周/每周学习时长趋势（折线图）
   * 横轴为星期一到星期日，纵轴为分钟数。
   * 配合“平均每日背词时间”基准线，激发用户的竞争欲。
